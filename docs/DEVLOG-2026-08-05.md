## 1. Terrain/asset classification fix

**Problem:** Dense metro seats (Bukit Bintang, Cheras, Petaling Jaya, Subang Jaya, Shah Alam, George Town, Johor Bahru, etc.) were being generated with rural assets (hills, kampung houses) instead of urban ones.

**Fix** (`app/data/constituencies.ts`):
- Added an `areaType: AreaType` field (`urban_dense` / `suburban` / `rural`) to `Constituency`.
- Curated `URBAN_DENSE_SEAT_NAMES` / `SUBURBAN_SEAT_NAMES` lists (~180 seats) built into lookup sets.
- `deriveAreaType(name, stateUrbanPct, popDensity)` blends the curated list with each state's `demographics.urban` for every uncurated seat, so classification degrades gracefully outside the curated list instead of defaulting to rural.
- Wired into `generateConstituencies()`'s per-seat loop.

**Fix** (`app/kawasan/page.tsx`):
- `deriveSeatTraits()`: the "hilly" flag was matching any seat with "bukit" in its name (a common word in seat names, not just literal hills) — narrowed to an explicit exception list (`bukit bendera`, `bukit antarabangsa`) plus the real keyword list.
- Building density is now clamped by the seat's `areaType` tier (urban_dense ≥0.85, suburban 0.3–0.62, rural <0.3) before it feeds the grid-size/skyscraper logic, so a metro seat can no longer roll into "rural sprawl" territory by chance.

## 2. LRT/MRT transit system (built from scratch, then iterated ~8 times)

- Elevated LRT/MRT track running through the middle of downtown (not hugging the map edge), with a real curved chamfer at the turn.
- Multi-lane road markings (dashed lanes + solid median) for metro-density roads.
- **Train shape rebuilt**: multi-carriage (3 cars), tapered nose caps on both ends (bidirectional cab), coupler gaps, window strips, 2-tone cyan/gold livery matching the game's theme, headlight only on the active lead car.
- **Turning through bends**: trains now actually rotate through the curve (per-waypoint heading computed via `atan2`), not just translate in a fixed orientation.
- **Lane separation**: forward/reverse trains now travel on perpendicular-offset paths so they don't visually merge when timing coincides; track widened for clearance.
- **Second route + interchange**: added Line 2 (appears at density ≥0.8), stacked at a different deck height to avoid Z-collision with Line 1 at the crossing, with a 2-level interchange station where the lines meet.
- **Track-through-buildings bug**: the curve's corner radius was cutting diagonally across the tallest downtown block. Fixed by constraining the radius to stay within the road's own width, so the curve never leaves the road regardless of building height.
- **Speed bug**: a route-length scaling factor was being applied twice, producing a 92-second lap that read as "frozen." Fixed to derive duration directly from the real route length.
- **Flattening bug**: the train's animated wrapper directly parented its 3D face divs, which is a known CSS-3D trap (animating a property on a `preserve-3d` ancestor flattens its children into a 2D composite). Fixed with the same static intermediate wrapper pattern already used for cars/boats.

## 7. Today's session: `/kawasan` visual polish + performance pass

1. **Label density by zoom** — non-primary zone name/stat cards fade out as the camera zooms out (driven by the existing `--kw-zoom` camera variable, zero new state), falling back to the existing hover tooltip. The primary zone (Pusat Bandar) always stays labelled as a landmark anchor.
2. **Zone score → color, smooth gradient** — added `scoreTintRGB()`: a continuous red→gold→green interpolation (not a hard cutoff at 54/74) driving both the zone ground tile's border/glow and every building's roof accent, so a zone at 73 vs 75 reads as nearly identical instead of jumping color.
3. **Reduced fog / better distant visibility** — pulled back `.kw-fog` and `.kw-farground` opacity/fade points so far zones don't disappear.
4. **Critical-zone pulse** — zones scoring below 54 get a pulsing red glow on their ground tile (`kw-zone-critical`), so they visibly demand attention even when zoomed out past the label threshold.
5. **Minimap** — new bottom-right corner overlay: a top-down grid of every zone tinted by its score, gold outline on the selected zone, and a compass wedge that reads the live camera rotation directly off the `--kw-rz` CSS variable (inherited for free — no extra per-frame JS).
6. **Performance pass** — `/kawasan` is a pure CSS-3D scene (no Three.js/React Three Fiber), so techniques like `InstancedMesh` or frustum culling don't apply, but the underlying complaint (movement feeling laggy) mapped onto a real issue: none of the scene's 8 leaf/zone components were memoized, so *any* unrelated state change (hover, time-of-day toggle, weather toggle, zone selection) forced React to re-reconcile the entire scene tree — measured at **12,641 DOM nodes / 685 buildings** on a dense metro seat (Petaling Jaya). Wrapped `Building3D`, `Car`, `Boat`, `TransitTrain`, `TransitPylon`, `TransitStation`, `EmptyPlot`, and `ZonePlot` in `React.memo`, and fixed `ZonePlot`'s `onSelect` prop (was a fresh closure on every render, which would have silently defeated its own memoization) to use the stable store setter directly. Vehicle/train movement itself was already compositor-only CSS `@keyframes` reading custom properties, not React state, so that part needed no change.

**Verification:** `tsc --noEmit` and `eslint` clean (only a pre-existing unrelated unused-var warning remains). Playwright pass on Petaling Jaya confirmed: zero console/page errors, drag-rotate and scroll-zoom both change the camera CSS vars, click-to-select still works, minimap renders, score-tinted borders render, and critical-pulse zones are present.
